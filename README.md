# Матчинг товаров маркетплейса

Kaggle-соревнование «[Intern] Binary classification: marketplace»: для пары «оффер продавца × товар каталога» определить, один ли это товар. 2.5 млн пар в train, метрика — F1.

## Результат

| Шаг | F1, holdout | F1, Kaggle |
|---|---|---|
| Скор организаторов + правило «один матч на оффер» | 0.748 (OOF) | — |
| LightGBM на табличных признаках | 0.7867 | — |
| Нейросеть-переранжировщик | 0.7876 | — |
| Смесь сети и LightGBM 50/50 | 0.7921 | 0.7951 |
| **Стекинг: предсказания сети как признаки LightGBM** | **0.7961** | **0.7981** |

Порядок решений на моём holdout совпал с лидербордом — валидации можно верить.

## Что нашёл в данных

- **Векторы названий товаров привязаны к id неверно.** Косинус «название оффера ↔ название товара» даёт ROC-AUC 0.50, как случайное угадывание. Эти векторы не использую.
- **Утечка через наличие фото.** Вектор фото есть у 99.9% подходящих товаров и только у 11% неподходящих. Один этот флаг поднимает F1 с 0.80 до 0.945. В продукте такой признак бесполезен, поэтому решение построено без него.

## Решение

1. **Признаки пары:** скор организаторов, место кандидата по скору и отрыв от лучшего, позиция в выдаче, цены, популярность товара, категория.
2. **Listwise-переранжировщик на PyTorch.** Сеть видит оффер и всех его кандидатов сразу. Кандидаты и отдельный токен «нет матча» проходят через Transformer-энкодер (2 слоя, 4 головы, d = 128) и сравниваются друг с другом. Softmax по кандидатам и «нет матча», потери — кросс-энтропия по правильному варианту. 689 тыс. параметров; AdamW, OneCycleLR, bf16, ранняя остановка.
3. **Стекинг.** OOF-предсказания сети — признаки для LightGBM, фолды у обеих моделей общие.
4. **Порог под F1** подобран по OOF-предсказаниям и проверен на holdout.

## Валидация

Офферы из test не встречаются в train, поэтому все разбиения сделаны целыми офферами: GroupKFold на 5 фолдов и holdout из 15% офферов, которого не видела ни одна модель.

## Как запустить

Ноутбук рассчитан на Kaggle с GPU. Данные соревнования в репозиторий не входят: подключите их через **Add Input**, путь определяется автоматически. Для быстрой проверки уменьшите `SAMPLE_OFFERS` в первой ячейке настроек.

Ноутбук воспроизводит итоговый пайплайн (сеть → стекинг с LightGBM). Лучший сабмит 0.7981 получен этим же пайплайном, где параметры LightGBM подбирал мой AutoML-агент.
